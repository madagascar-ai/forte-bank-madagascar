# Общий сервер и независимая разработка

У команды один репозиторий и один общий сервис для интеграционных проверок. Каждый участник работает в своей ветке и отдельной рабочей папке. Эта папка может находиться на его компьютере или на общем Mac при удалённой разработке.

```text
Рабочая копия участника → ветка → pull request → тесты → main
                                                       ↓
                                    развёртывание общего сервиса
```

## Текущее состояние

- Общий сервис запускается на Mac по адресу `127.0.0.1:8000`.
- CI выполняет синтетические тесты, lint и проверку JavaScript/Compose при push и pull request.
- Доступ команды в одной Wi-Fi сети ограничивается списком IP; VPN и SSH подключаются отдельно. `localhost` доступен с самого Mac.
- Для автоматического обновления после успешного CI реализован [агент деплоя на Mac](autodeploy.md). Его установку и состояние проверяют командами из этой инструкции.

## Обычная разработка

На собственном компьютере достаточно Python 3.11+ и Git; для команд Makefile нужен `make` (macOS/Linux/WSL).

```bash
git clone https://github.com/temirrrr/forte-bank-madagascar.git
cd forte-bank-madagascar
git switch -c feat/my-change
make setup
make demo
make serve PORT=8001
```

`make demo` сохраняет явно подписанный синтетический результат. Это позволяет работать над API, UI и последующими этапами без YOLO и Ollama. Для реальных прогонов установите `make setup-vision`, подготовьте веса через `make models` и загрузите модель Ollama из `.env`. На Windows без WSL команды Python приведены в README.

После изменения выполните `make check`, отправьте ветку и откройте pull request. Общие контракты согласуются до слияния; отдельные модули можно улучшать независимо.

## Просмотр общего сервиса

В одной Wi-Fi сети можно ограничить доступ конкретными ноутбуками. В `.env` владельца задаются `FORTE_HOST=0.0.0.0` и `FORTE_ALLOWED_CLIENTS=IP_УЧАСТНИКА_1,IP_УЧАСТНИКА_2`, затем сервис перезапускается. Список принимает только отдельные адреса, доступ с loopback сохраняется. Внешние устройства вне списка получают 403 на всех маршрутах, а разрешённым устройствам дополнительно нужен API-ключ. После смены Wi-Fi адреса список обновляется. Возможность соединения между ноутбуками зависит от настроек кампусной сети.

Для удалённого доступа можно создать частную сеть команды через Tailscale и разрешить нужным людям доступ к Mac. Каждый участник подключается под своей учётной записью; для SSH используются его публичный ключ и разрешённая локальная учётная запись Mac. Конкретные пользователи и разрешения задаются при подключении команды.

После настройки VPN и SSH тиммейт может открыть туннель:

```bash
ssh -N -L 18000:127.0.0.1:8000 TEAM_USER@MAC_PRIVATE_ADDRESS
```

Затем открыть `http://127.0.0.1:18000` на своём компьютере и ввести ключ общего сервиса, полученный от владельца по согласованному каналу. Сам API продолжает слушать loopback на Mac. Адрес и пользователь в команде выше — placeholders, доступ этим документом не создаётся.

## Работа прямо на Mac

Участник подключается через VS Code Remote SSH (или другой редактор с поддержкой SSH) и открывает свою рабочую копию. Она имеет свою ветку, окружение, ключ, каталог задач и порт. Пример распределения: общий сервис — 8000, рабочие копии — 8001, 8002, 8003.

Для просмотра своего dev-сервера участник перенаправляет соответствующий порт в редакторе или через `ssh -L`. Его изменения проходят обычный pull request перед обновлением общего сервиса.

Тяжёлые прогоны на Mac запускаются по очереди: очереди отдельных dev-серверов сейчас не координируют нагрузку между собой. Модели и реальные видео можно оставить на общем Mac; переносить их в Git для совместной работы не требуется.

## Автоматическое обновление

На Mac локальный агент проверяет успешные тесты для `main`, готовит проверенную версию и проверяет `/api/v1/readiness` после переключения. Установка описана в [инструкции автодеплоя](autodeploy.md). Для отдельного Linux-сервера впоследствии можно подключить доставку Docker-образа и обновление Compose.

Рабочие копии участников и каталог общего сервиса раздельные. Данные задач, веса и секреты хранятся отдельно от обновляемого кода.

Официальные инструкции: [GitHub pull requests](https://docs.github.com/en/pull-requests/reference/pull-requests), [Tailscale machine sharing](https://tailscale.com/docs/features/sharing), [VS Code Remote SSH](https://code.visualstudio.com/docs/remote/ssh).
