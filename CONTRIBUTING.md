# Работа команды

Подробная схема и подключение к серверу: [командная разработка](docs/team-development.md).

1. Клонируйте репозиторий в свою рабочую папку и создайте ветку: `git switch -c feat/short-description`.
2. Выполните `make setup`. Для работы над детектором используйте `make setup-vision`.
3. Для проверки интерфейса без YOLO и скачивания LLM выполните `make demo`, затем `make serve PORT=8001`. Ключ своей копии — в `.env`.
4. Работайте в своём модуле. Форматы между этапами определены в `src/forte_guard/contracts.py`.
5. Выполните `make check`, отправьте ветку и откройте pull request в `main`.
6. В pull request укажите, что изменилось и как проверено. Изменение контракта согласуйте с участниками соседних этапов.

Синтетический пример проверяет интеграцию после детектора. Настоящая обработка видео требует подготовленных весов и локального Ollama.

## Границы модулей

| Область | Файлы | Выход |
| --- | --- | --- |
| Объекты и треки | `src/forte_guard/vision/`, `config/detector.json` | `ObjectJournal` |
| Действия, состояния, роли | `src/forte_guard/journal/` | `ActionJournal` |
| Правила и локальная LLM | `src/forte_guard/reasoning/`, `config/rules.json`, `config/scenarios.json` | `Candidate[]` |
| API и интерфейс | `src/forte_guard/api.py`, `src/forte_guard/web/` | HTTP / UI |

Видео, кадры, журналы реальных операций, веса и `.env` остаются в локальном контуре. Тесты и примеры в репозитории используют синтетические данные. У каждого checkout собственные `.venv`, `.env` и `data/`.
